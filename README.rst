==============
imio.omnia.ocr
==============

A machine-generated text version of PDF files for Plone 6, part of the
`Omnia <https://github.com/IMIO/imio.omnia.core>`_ suite by iMio.

Many published PDF files are scans without a text layer. A screen reader
cannot read them and a search engine cannot index them. This package sends
the PDF file of a content item to the Omnia OCR API, stores the text that
comes back, and gives the host package what it needs to show the text and to
index it.

The text is generated by a machine and nobody reviews it. It is always shown
with a disclaimer: only the PDF file is authoritative.


Features
========

- **Opt-in by behavior** — the marker behavior ``imio.omnia.ocr`` has no
  schema field. A host package enables it on a Dexterity type.
- **No modified event** — the text is stored in an annotation. The package
  never sends ``ObjectModifiedEvent``, never changes the modification date and
  reindexes only ``SearchableText`` and ``ocr_status``.
- **Generation in its own request** — saving the content only marks the file
  as ``pending``. A small script starts the generation for a user who can
  manage the text version.
- **Stale text is dropped at once** — when the file changes, the old text is
  removed and the file is ``pending`` again.
- **Safe HTML** — the Markdown of the OCR becomes HTML on the server. It keeps
  only the tags of a text document, then it goes through the HTML filter of
  Plone.
- **Low confidence** — a threshold and three modes: show with a stronger
  warning, hide, or show but keep out of the search.
- **Per file field** — the primary field by default, any other file field on
  request.


Installation
============

Add the egg to your buildout::

    [buildout]

    ...

    eggs =
        imio.omnia.ocr

Then run ``bin/buildout`` and install the add-on. The package is auto-included
in Plone via ``z3c.autoinclude.plugin``. Its profile depends on the profile of
``imio.omnia.core``, which holds the URL and the credentials of the Omnia API.


Use in a host package
=====================

1. Enable the behavior on a type (``profiles/default/types/MyType.xml``)::

    <property name="behaviors" purge="False">
      <element value="imio.omnia.ocr"/>
    </property>

2. Add the text to the ``SearchableText`` indexer of the type::

    from imio.omnia.ocr.api import searchable_text

    text = searchable_text(obj)

3. Show the text and the manage panel in the view template::

    <tal:ocr define="ocr context/@@ocr-info">
      <div tal:replace="structure context/@@ocr-manage-panel" />
      <section tal:condition="ocr/available">
        <h2>Text version</h2>
        <p tal:content="ocr/disclaimer" />
        <div tal:content="structure ocr/html" />
        <a tal:condition="ocr/truncated"
           tal:attributes="href ocr/full_text_url">Full text</a>
      </section>
    </tal:ocr>

   The panel contains a ``form``. Do not put it inside another form.

4. Generate the text of the existing content with a script
   (``bin/instance run``)::

    from imio.omnia.ocr.api import process

    status = process(obj)   # "done", "failed", "pending" or None
    transaction.commit()

   ``process`` calls the API only when the text of the current file is missing
   or ``pending``. ``process(obj, force=True)`` always calls the API. An answer
   of the API without text (for example for a damaged file) gives ``failed``.


Views
=====

All the views are registered for content with the behavior.

=========================  ==========  ============================================
View                       Permission  Purpose
=========================  ==========  ============================================
``@@ocr-info``             View        Helper for templates: ``status``,
                                       ``available``, ``low_confidence``,
                                       ``page_count``, ``html``, ``truncated``,
                                       ``text_url``, ``full_text_url``,
                                       ``can_manage``, ``disclaimer``
``@@ocr-text``             View        Page with the disclaimer and the full text
``@@ocr-text-fragment``    View        The same HTML as a bare fragment
``@@ocr-manage-panel``     View        Status and buttons for the managers. Empty
                                       for the other users
``@@ocr-process``          Manage      POST. Runs the generation, answers JSON
``@@ocr-manage``           Manage      POST. ``action`` is ``regenerate``, ``hide``
                                       or ``show``
``@ocr-text`` (REST API)   View        Status, page count, confidence and pages
=========================  ==========  ============================================

"Manage" is the permission ``imio.omnia.ocr: Manage text version``. The default
roles are Manager, Site Administrator, Editor and Owner.

``@@ocr-text``, ``@@ocr-text-fragment``, ``@@ocr-process`` and ``@@ocr-manage``
accept a ``fieldname`` parameter for a file field that is not the primary
field. ``@@ocr-text-fragment`` also accepts ``heading_level``.


Rendering
=========

- Markdown tables and the HTML tables of the API stay tables.
- Only the tags of a text document stay: headings, paragraphs, lists, tables,
  links and emphasis. The OCR copies the HTML code that a document shows. Such
  code loses its tags (for example ``iframe``) and all its attributes.
- A link stays a link only when its target is a web address or a mail address.
- Headings are shifted: the highest heading of the text becomes ``h3`` (``h2``
  on the ``@@ocr-text`` page) and no heading goes below ``h6``.
- An image with a description becomes a short text ("Image: description").
  An image without a description is removed.
- Each page is a ``section`` with a label ("Page 3") for screen readers.
- Page headers and footers are stored but they are not rendered.


Configuration
=============

The settings are in the **OCR** tab of the Omnia control panel
(``@@omnia-ocr-settings``). The registry prefix is
``imio.omnia.ocr.interfaces.IOmniaOcrSettings``.

============================  ==========  =====================================
Field                         Default     Purpose
============================  ==========  =====================================
``enabled``                   ``True``    Generate text versions. When off, no
                                          file is sent to the OCR. Existing
                                          texts stay visible
``runner``                    ``sync``    Name of the ``IOcrRunner`` utility
``timeout``                   ``330``     Timeout of the OCR call, in seconds
``extract_header_footer``     ``True``    Separate page headers and footers
``html_tables``               ``True``    Ask for HTML tables
``image_descriptions``        ``False``   Ask for a description of the images.
                                          A description can be wrong
``confidence``                ``True``    Ask for confidence scores
``low_confidence_threshold``  ``0.7``     Below this score, the confidence is
                                          low
``low_confidence_mode``       ``warn``    ``warn``, ``hide`` or ``noindex``
``inline_max_pages``          ``50``      Pages given by ``@@ocr-info/html``
============================  ==========  =====================================

After a change of ``low_confidence_threshold`` or ``low_confidence_mode``,
reindex ``SearchableText`` of the content.


Extension points
================

- ``IOcrText`` — adapter that reads and writes the stored text:
  ``IOcrText(obj)``, or ``imio.omnia.ocr.api.get_text(obj, fieldname)``.
- ``IOcrRunner`` — named utility with ``run(obj, fieldname=None)``. The
  ``sync`` runner does the OCR in the current request. Register another
  utility (for example a task queue) and select it in the settings.
- ``ocr_status`` — catalog ``FieldIndex`` with ``pending``, ``done`` or
  ``failed``.
- ``imio.omnia.ocr.processed`` — DOM event sent by the script of the manage
  panel when a generation ends. Call ``preventDefault()`` to stop the reload
  of the page.
